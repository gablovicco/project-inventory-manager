# Development Method

## Selected Method

The project will use Scrum with selected Extreme Programming (XP) practices, adapted for individual development.

## Rationale

Scrum was selected because the course structure already organizes the project around Sprint 0 followed by three implementation iterations.

The project will therefore use the following Scrum practices:

- a prioritized Product Backlog;
- a goal for each sprint;
- sprint planning;
- incremental implementation;
- a working increment at the end of each sprint;
- sprint review;
- sprint retrospective;
- backlog changes based on implementation experience and feedback.

The project is developed by one student, who is me, so some team-oriented Scrum activities will be simplified.

There will be no separate Scrum Master, Product Owner or development team roles. The developer will be responsible for maintaining the backlog, planning the sprint, implementing the selected work and reviewing the outcome.

The purpose of keeping the Scrum structure is not to reproduce a full professional Scrum team, but to make the development process visible, iterative and easy to evaluate.

## XP Practices

Selected XP practices will be used to support software quality:

- automated testing;
- continuous integration;
- small and incremental changes;
- frequent commits;
- refactoring when necessary;
- keeping the design as simple as possible.

These practices are particularly useful for this project because they help detect problems early and keep the code understandable as new functionality is added.

## Adaptation for Solo Development

Because the project is developed individually with instructor approval, team-oriented practices will be adapted rather than artificially reproduced.

For example:

- sprint planning will be performed individually;
- sprint reviews will evaluate the completed product increment against the sprint goal;
- retrospectives will focus on the developer's workflow, difficulties and improvements;
- code review will use self-review where appropriate unless the instructor requires external review;
- work will still be tracked through issues, branches, commits and pull requests to preserve traceability.

## Expected Benefit

This approach provides enough structure to demonstrate iterative development while remaining practical for a single developer.

Scrum provides the project-management structure, while the selected XP practices support code quality and continuous verification.
